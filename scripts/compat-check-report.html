结论：方案可行，已落地

在 git pre-commit 阶段通过静态分析检测跨平台兼容性问题是可行的。已实现轻量级检查器（零依赖、纯 Node.js），覆盖 9 条规则，成功检测出 3 个真实 BUG 和 24 个需人工确认的风险点。检查器已安装为 pre-commit hook，将在每次 git commit 时自动运行。

检测到的真实 BUG

BUG 1: wx.login 裸露 ERROR

文件: pages/login/login.vue L46

const { code } = await wx.login();

问题：wx.login() 是微信小程序专有 API，在 H5 和 App 端会直接报错。该方法未被 #ifdef MP-WEIXIN 包裹。

修复建议：用 // #ifdef MP-WEIXIN 包裹，或改用 uni.login() 跨平台 API。

BUG 2: window.open 在非 App 块中 ERROR

文件: uni_modules/stellar-ui/components/ste-app-update/ste-app-update.vue L327-332

// #ifdef APP-PLUS
plus.runtime.openURL(resp.data.downloadUrl);
// #endif
// #ifndef APP-PLUS
window.open(resp.data.downloadUrl, '_blank');
// #endif

问题：#ifndef APP-PLUS 覆盖了 H5 + 所有小程序平台，但 window.open() 仅在 H5 可用。小程序端会崩溃。

修复建议：将 #ifndef APP-PLUS 改为 #ifdef H5。

BUG 3: 事件绑定拼写错误 WARN

文件: uni_modules/stellar-ui/components/ste-signature/ste-signature.vue L2

@mosueleave="onTouchEnd"

问题：@mosueleave 应为 @mouseleave。当前 H5 端鼠标离开签名区域时事件不会触发，导致签名画布无法正确结束。

使用方式

npm 命令

npm run compat:check         # 检查 staged 文件（pre-commit 默认）
npm run compat:check:all     # 检查全项目 .vue/.js 文件
npm run compat:check:file -- --file path/to/file.vue  # 检查指定文件

pre-commit 自动检查

hook 已安装。每次 git commit 时自动运行：

  • 无 ERROR → 提交成功（有 WARNING 也会通过）
  • 有 ERROR → 提交被阻断，需修复后重新提交
  • 跳过检查（不推荐）：git commit --no-verify

新环境安装

clone 项目后执行 npm install，prepare 脚本会自动安装 hook。

手动安装：node scripts/setup-compat-hook.js

扩展规则

在 scripts/compat-rules.js 中添加新规则对象即可：

{
    id: 'R10',
    name: '新规则名称',
    severity: 'error',
    platforms: ['MP-WEIXIN'],
    blockTypes: ['script', 'template'],
    pattern: /somePattern/g,
    exempt: ['H5'],
    message: '问题描述: {match}',
}

局限性

能检测的

  • DOM/BOM API 是否在正确的条件编译块内
  • 平台专有 API（wx.*）是否被守护
  • 条件编译指令配对性
  • renderjs 块的平台守护
  • 已知拼写错误的模式匹配
  • CSS 固定定位使用提醒

不能检测的

  • 运行时行为差异（如 fixed 在 scroll-view 内实际是否失效）
  • CSS 渲染差异（各端默认值不同）
  • 事件传播冒泡差异
  • 逻辑分支的正确性（条件编译覆盖了所有平台但逻辑有误）
  • 性能特征差异

这些需要通过端到端测试和真机/模拟器回归测试来覆盖，不属于静态检查的范畴。
